# 发布检查与验收（GOV-04）

入口：仓库根目录运行 `python -B scripts/check_data_release.py`。
依赖 Python 3.12+ 和 Git；不新增第三方包。`--root` 可指定另一个 Git 仓库根目录。
只读检查，不修改文件、不暂存、不提交、不推送；通过退出 0，拒绝退出 1，参数错误退出 2。

## 两份快照分别检查

1. 工作区：遍历 `data/public/` 和 `data/sources/`，包含忽略及未跟踪文件；
   拒绝符号链接、Windows junction、未登记文件、缺失文件、权限不符或哈希变化。
2. Git 索引：从 `git ls-files --stage -z` 获取暂存条目的模式及 blob ID，
   使用捕获的 blob ID 读取清单和正文，不用工作区内容替代暂存内容。
   暂存区中的清单及正文也要分别通过再分发准入与内容扫描。
3. 整个索引检查禁止路径：四类隔离／历史生成目录、`.env` 及非 example 变体、
   已知凭证文件名及 `.pem/.key/.p12/.pfx`；拒绝符号链接、子模块及未合并条目。
4. 公开数据内容及登记清单只接受 UTF-8 文本（txt/md/json/jsonl/csv），上限 8 MiB；
   拒绝不支持的文件类型、非法 UTF-8 或控制字符。压缩包不能仅改名为 txt 后放行。
5. 对公开内容、清单和文件名匹配部分手机号、邮箱、证件号、密钥模式；
   输出仅错误代码、经过筛查的相对路径或来源行索引，不打印命中文本。

`data/sources/` 目前只允许登记清单，不允许把未审阅的候选登记或合同顺带发布。
候选资料与真实授权证据应按治理政策留在受控位置，核验非敏感元数据后才导入可用清单。
源许可未知、用途拒绝、过期、撤回或上游权限不足时，不能仅修改哈希通过准入。

## 提交顺序

```powershell
python -B -m unittest discover -s tests -v
git diff
git add -A
git diff --cached
python -B scripts/check_data_release.py
# 检查差异，写入 docs/git-diffs/<日期>-<描述>.md
git add -A
git diff --cached --check
python -B scripts/check_data_release.py
# 确认所有检查成功，再执行 commit 和 push；不要忽略非零退出码。
```

先暂存后检查很重要：工作区恢复干净，不会清除暂存区中旧的敏感内容。
受限目录一旦被 `git add -f` 强制加入，检查仍应拒绝。
检查是本地手动关卡；本周没有配置服务端强制保护、自动 Git hook 或常驻监控。

## 验收与限制

- 临时 Git 仓库测试覆盖：强制暂存、正文／清单暂存不一致、未登记与忽略文件、
  许可检查、敏感模式、正确哈希但敏感的内容、二进制／压缩包、缺失清单、退出码及脱敏。
- Windows junction 实测拒绝；Git 索引符号链接模式可在无本机 symlink 权限下测试。
  GOV-03 的真实文件 symlink 测试在本机仍因权限跳过，不能写为全部无跳过。
- 模式扫描不是法律鉴定、全面 DLP 或个人信息匿名化认证，有误报与漏报。
- 内容扫描仅覆盖上述新公开目录与清单；不覆盖其他历史文档、Git 历史、外部附件、
  Release 或受限数据原文。整个提交仍须检查，不应把关卡通过称为全仓安全认证。
- 目录与文件名规则为保守子集，不支持所有平台路径或文件类型；不支持并发修改时的原子发布保证。
- 历史标准映射、合成资料和旧 Golden 未取得新的权利或科学性认可。
- 技术 fixture 的通过不等于真实数据获准，专家标注和 NLP 实验尚未进行。
