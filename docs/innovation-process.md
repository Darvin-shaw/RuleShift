# 创新提案与联动更新流程

本文档规定项目开发过程中发现、评估、纳入和验收创新点的统一流程。目标是在保持项目聚焦、
数据合规和结果可验证的前提下，让有价值的新想法能够进入实际开发，而不是停留在口头建议。

## 1. 适用范围

下列变化应进入创新提案流程：

- 新的 NLP 任务定义、数据构造方法、模型方法或评测指标；
- 新的检索、推理、本体、证据链或版本演化机制；
- 新的 MCP、Agent、Skill、外部模型或平台集成方式；
- 能显著提升科研价值、产品价值、可信性、性能或可复现性的工程方案；
- 会改变数据来源、许可范围、隐私/安全边界、开发成本或里程碑的想法。

普通缺陷修复、等价重构、文案纠错和依赖例行升级不单独登记创新，但仍按正常变更流程维护文档和测试。

## 2. 影响分级

| 级别 | 判断标准 | 处理方式 |
|---|---|---|
| L1 局部改进 | 不改变目标、数据边界、核心架构、外部依赖和总体排期 | 汇报后可在当前授权任务中实施 |
| L2 模块创新 | 新增模块、数据字段、评测维度或跨模块接口，影响可在当前里程碑内消化 | 汇报影响和验收方案，确认优先级后实施 |
| L3 方向变更 | 改变研究问题、数据许可/合规边界、核心架构、模型路线、外部服务、预算或排期 | 用户明确确认后再实施 |

无法判断级别时按较高一级处理。

## 3. 标准流程

1. **发现**：记录现有问题、触发证据和想法来源。
2. **提案**：使用第 4 节模板，明确创新点、基线、假设和验收方法。
3. **汇报**：向用户说明收益、代价、风险、影响文件和推荐级别。
4. **决策**：记录“候选 / 已批准 / 暂缓 / 拒绝”；L3 必须有明确确认。
5. **纳入 WBS**：分配 `INNO-YYYY-NNN` 和实现任务编号，写入依赖、负责人和里程碑。
6. **实施**：代码、数据、配置、测试和文档同步开发。
7. **验证**：与既有基线比较；没有可复现证据时不得宣称创新有效。
8. **联动更新**：按第 5 节影响矩阵更新所有适用产物。
9. **验收**：台账记录结果、限制、关联提交和后续事项。

## 4. 提案模板

```markdown

- 发现日期：
- 提出者：
- 影响级别：L1 / L2 / L3
- 当前问题与证据：
- 创新内容：
- 与现有方案/基线的差异：
- 科研或应用价值：
- 可行性依据：
- 数据来源与许可影响：
- 技术、成本、排期和风险：
- 受影响文件/模块：
- 实施任务与依赖：
- 验收指标及基线：
- 决策：候选 / 已批准 / 暂缓 / 拒绝
```

## 5. 联动影响矩阵

| 变更类型 | 必查产物 |
|---|---|
| 项目目标或研究问题 | README、总体方案、WBS、里程碑、演示脚本 |
| 数据来源或样本结构 | 数据治理/来源清单、数据规格、Schema、生成器、Dataset Card、测试 |
| 本体或规则表示 | Schema、种子/候选数据、映射、审核流程、MCP、回归测试 |
| 检索或推理方法 | 架构文档、核心代码、Agent/Skill、Golden 集、评测基线 |
| MCP/API/外部服务 | 接口 Schema、服务包装、Agent 蓝图、部署配置、安全说明、联调测试 |
| 模型、提示词或训练方法 | 模型/数据卡、参数配置、成本说明、基线/消融实验、回滚条件 |
| 指标或验收口径 | 评测代码、Golden 标注、里程碑状态、README 中的结果说明 |

不适用的产物无需机械修改，但应在提案或创新台账中记录“不适用”及原因。

## 6. 完成定义

创新只有同时满足以下条件才可标记为“已完成”：

- 预设验收指标有可复现结果；
- 相关测试通过，原有能力无不可接受退化；
- 数据来源、许可、隐私和安全影响已复核；
- 受影响的代码、Schema、配置、文档、计划和演示材料已同步；
- `docs/innovation-log.md` 已记录结果、限制和关联任务；
- 提交时已生成对应的 `docs/git-diffs/` 变更总结。
