# RuleShift 数据治理（GOV-02）

日期：2026-09-07。本文是项目准入政策，不构成法律意见或合规认证。

## 1. 来源与证据

| 类别 | 获取途径 | 必须核实 | 默认用途 |
|---|---|---|---|
| A 官方 | 发布机关官方网站、正式出版渠道 | 发布主体、版本、生效时间、适用范围、逐项权利 | 只登记待核验元数据，不自动获取正文 |
| B 企业授权 | 企业权利人书面授权、安全传输 | 签署权限、保密要求、用途与期限、个人信息处理条件 | 隔离，未获授权不得采集 |
| C 科研许可 | 原作者／机构数据主页、正式仓库 | 数据自身许可、上游权属、引用与撤回要求 | 未核验前不下载和训练 |
| S 原创合成 | 本项目明确标记的自编内容 | 作者方式、生成过程、上游血缘、非真实标准声明 | 仅按明示用途使用 |

权威性不等于可使用性，哈希一致不等于内容真实。来源 URL 不能代替授权证据。
国家标准平台区分全文阅读、下载与题录；平台可访问性不作为本项目的训练或再分发许可。
核验入口：[国家标准全文公开系统](https://openstd.samr.gov.cn/bzgk/std/)（2026-09-07 查阅）。
真实标准、科研数据和企业数据进入 DATA-01 时须重新核验届时条款，并保留核验日期。
不得绕过访问控制、付费限制或批量抓取限制。摘要、翻译、问答和向量等派生物仍需核查上游权利。

## 2. 准入流程与职责

1. 数据治理角色登记候选来源，只保存非敏感元数据；未获收集依据不先下载原文。
2. 核验权属、用途和期限，授权证据正文置于仓库外受控存储；公开登记仅写非敏感证据编号。
3. 核对版本、生效关系和内容真实性，并检查哈希、路径和血缘；可由机器完成并记录核验方式。
4. 分别批准 `research`、`model_input`（本地推理）、`training`、`external_model`、`redistribution`。
   必须为 JSON 布尔值；缺失、未知、过期、撤回或用途不符一律拒绝。
5. 技术 CLI 检查登记的一致性；不生成、不模拟人工签名或法律授权。
6. 发布前检查公开资料及实际 Git 暂存区，记录检查结果。授权变化时停止相关使用，
   沿血缘找出派生样本／索引／训练产物，隔离并评估撤回和重建；不得认为删除原文即清除历史影响。

`technical_fixture` 审查仅限 S 类原创演示，必须显示技术自检身份，不冒充专家。
真实材料支持 `machine` 核验，记录机器身份、日期和来源依据链接，不要求人工审查或签核。
`human` 仅兼容历史记录；CLI 检查记录一致性，不把字段齐全视为权利依据真实有效。

## 3. 存储与发布边界

| 路径 | 用途 | Git 政策 |
|---|---|---|
| `data/sources/manifest.json` | 非敏感来源、用途、血缘登记 | 检查通过后可发布 |
| `data/public/` | 已准入的 UTF-8 文本与公开数据卡 | 按登记、哈希、权限、模式扫描检查 |
| `data/restricted/` | 受限数据本地暂存预留 | 禁止提交，实际原文优先存工作区外 |
| `data/quarantine/` | 待核验或撤回数据预留 | 禁止提交，不代表允许先收集 |
| `data/derived/` | 未获公开许可的派生物 | 禁止提交；公开副本须独立登记到 public |
| `data/generated/` | 历史 EvoNex 合成产物 | 不作为新研究数据自动准入，禁止直接强制提交 |

`.gitignore` 不是加密、访问控制或 DLP；对已跟踪和 `git add -f` 无保护。
GOV-04 检查实际 Git 索引，不能仅依靠忽略规则。公开检查不支持的二进制／压缩包默认拒绝，
不得改名绕过。历史仓库其他数据尚未迁移到新登记，不因 W1 检查通过而获得研究或再发布批准。
敏感模式检查只能发现部分手机号、邮箱、证件号和密钥模式，有误报与漏报；不得称为零泄露保证。
不得在日志或报错中回显命中的敏感原文。发布检查覆盖公开登记、文件名与所有提交内容。

## 4. 科学性与验收

- 合成数据只验证工程链路；不声称权威规程、真实修订或专家 Golden。
- 数据卡记录样本数、来源类别、作者方式、标注方式、限制、版本和划分单位。
- 使用机器标签并保留算法来源和不确定项，不声称人工或专家裁决；文档族和其派生问答不得跨数据集划分。
- 自然修订、合成挑战、真实企业案例分开计量，尚未获得的集合标记未评估。
- GOV-02 验收：上述流程、权限、存储、科学性与历史限制齐备；不涉及真实数据准入。
- GOV-03 实现 JSON 登记与只读准入；GOV-04 实现发布扫描和对抗测试。

实现入口：[登记接口](source-registry.md)、[发布检查](data-release-check.md)。
W1 仅完成技术关卡；真实权利核验与科研标注需单独记录，不能用技术测试替代。

实现采用 JSON 而非 YAML，以复用 Python 标准库，避免 W1 新增外部依赖。
