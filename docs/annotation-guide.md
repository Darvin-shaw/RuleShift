# W2 标注准备与 W3 人工验收

日期：2026-09-08；关联 DATA-03、INNO-2026-002。

## 本周交付

从 DATA-02 的 12 对修订样本导出 24 条盲标任务，每条只包含一个版本、相同事实、
命题和目标日期，不提供程序候选答案。两个标注者独立填写；不向标注者分发原候选文件。
当前仅三个合成文档族，24 条判断；不足计划的 50 条试标，不以复制或改 ID 凑数。
W3 扩充合格材料至 50 条后开展人工试标，再决定 200 条规模和冻结划分。

## 标签与证据

- 支持：完整条款及给定事实足以推出命题，且适用例外不阻止结论。
- 否定：条款及事实明确推出不允许放行；不能仅因缺少支持证据而选否定。
- 无法确定：决定性事实不足或适用关系无法确定；填写缺失事实字段名。

只使用给定版本，不用新版回溯改写历史判断。日期区间左闭右开。
`evidence` 填当前条款中连续、非空的原文；`reason` 解释条件、否定及例外如何影响结论。
`missing_facts` 为字段名列表，没有则为空。示例中的缺陷数不得自行补为零，
未知污染状态不得当成无污染；不相关颜色不影响结论。

## 操作

在仓库外的受控目录生成两个独立文件（目录须尚不存在）：

```powershell
python -B scripts/annotation_tasks.py export --output D:/ruleshift-labeling/w2
python -B scripts/annotation_tasks.py check D:/ruleshift-labeling/w2/annotator-a.json
```

填写顶层 `annotator` 为人员代号，并逐条填写 `label`、`evidence`、`missing_facts`、`reason`。
初始 label/evidence/reason 为 null，因此空白表检查必然失败。校验失败只输出错误码，不回显原文。
任务标识、版本、事实和日期不可修改；输入样本 SHA-256 绑定导出时的精确内容。
工具检查完整性及证据是原文片段，不能判断证据语义是否足够，也不能核验人员真实身份。

## W3 完成条件（本周不执行）

两名独立标注者完成试标，领域复核者逐项裁决分歧，保留两份原标签、裁决及理由。
报告有效条数、原始一致率、各标签计数、分歧类型；不得把程序候选当作第三位专家。
按文档族和近重复血缘分组，同族版本及派生问答不得跨训练、开发、测试。
冻结清单记录样本与来源哈希、用途审批、划分、裁决记录和版本号；权限未通过不能冻结。
本工具不生成冻结清单，不把格式通过表述为人工验收通过。
